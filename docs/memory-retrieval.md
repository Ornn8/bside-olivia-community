# Situational recall and original-text retrieval

Canonical letters and the read-only Archive remain the durable sources. An independent SQLite index preserves full user and assistant text, timestamps and source IDs. Chinese bigrams and Latin tokens support local FTS5 matching; semantic Mem0 hits locate originals through source IDs. Candidates are grouped by source before combining semantic and per-topic full-text rankings. Complete exchanges are preserved together instead of cutting off the assistant's answer. Summary-only records remain available where no original survives.

The shared reply assembler freezes recent conversation and the daily-life view, collects a `RecallResult`, and renders that snapshot for the final request. Capacity retries repack the same records without searching again. Query clauses (including commas and semicolons) use one consistent topic numbering scheme. Final rendering records included/omitted groups and topic coverage. `evidence_found` means candidates reached the prompt, not that their claims are true. No match, unavailable sources, and evidence omitted for capacity are distinct outcomes; none proves that an event never happened.

Archive retrieval remains active when only part of the corpus is indexed. Individual clause queries plus one local scan of imported originals handle Chinese matches that the older Archive tokenizer misses. This requires no extraction-model request. Current and Archive evidence are fused before final packing. No new index or permanent copy is created by this read.

Daily-life source pointers can request originals even when the first search has zero hits. Explicit sources are read before time-adjacent indexed exchanges. Tracing is limited to two rounds and stops on no new evidence, missing sources, disabled reads, or the depth limit. Neighbors provide context, not proof of the same event. Undated records do not gain chronological neighbors by guess. Existing Archive, history-index, relationship-batch, and backup aliases resolve to the stored pair; text similarity alone does not establish identity. Later successful reads of other sources do not erase an earlier unresolved failure.

Stored `canonical` identity is distinct from fact confirmation. Prompts distinguish user claims, historical assistant replies, plans, completed events, and corrections. Current home access and other action permissions do not decide whether a past shared experience occurred. Reading history grants no new access or intimacy and changes no relationship scores or stages. World-state failures are marked unavailable rather than represented as verified empty relationships.

New exchange indexing precedes paid fact extraction. The existing outbox also backfills completed canonical letters, including terminal deliveries, in batches of twenty successful indexes per scan without invoking extraction. Each scan additionally indexes up to twenty imported Archive exchanges (official history, recovered offline pairs, and text backups). Existing imports need no reimport; unavailable adapters are retried on later scans. Content changes are reindexed, while forgotten sources remain tombstoned after restart. The Archive remains the durable read-only owner. Persona evidence and relationship state are not copied or reassessed.

Original timestamps accompany retrieved passages. Relative dates such as today/yesterday refer to that source date, not retrieval or import time. Undated offline pairs retain an unknown timestamp. Archive import time is used only for lifecycle controls, never as the original letter date. The background index uses the enabled conversation-memory adapter and obeys pause/clear controls; it does not install missing components or call an extraction model.

Product reply paths retain the recall-first capacity configuration and the request's input ceiling. The generic small-budget renderer remains available to callers that explicitly select it. Whole source groups are included or omitted together. The local token estimator is conservative, not a provider tokenizer or billing measurement. Current request source IDs are excluded across retrieval and tracing; incomplete recent excerpts do not justify excluding an entire historical exchange.

Evidence search caches up to 64 queries for 30 seconds, partitioned by user, query, limit, exclusions and index modification time. Pending provider writes bypass cache. Writes, manual additions, deletes and clears invalidate the in-process cache; failed provider searches are not cached.

Lifecycle controls guard background indexing. Source deletion and memory clear remove indexed originals and leave source tombstones so backfill cannot silently restore them. This does not erase the user's mailbox. Pausing Mem0 blocks its source reads while preserving independently permitted Archive reads. Forgotten aliases and failed forgetting guards apply to Archive and tracing as well. Export/import preserves explicitly unknown original dates instead of substituting import time. No original text or queries are added to diagnostic output.

Before live generation, a shared read-only check uses the configured model to interpret the frozen source window. It distinguishes assertion status, event stage, source scope and conflicts, and must cite verbatim text from the named source. Quotes are validated against decoded text, including Unicode line separators and quoted/multiline chat messages. Matched historical quotes retain the actual speaker, original reference and nearby source text; a user claim cannot gain an assistant source label. On success, generation receives the relevant findings and their cited local evidence instead of the whole retrieved original-text window. Recent conversation, its timestamps, canon and current world state remain intact. Full paired originals remain in the archive and frozen retrieval snapshot. Source identity and quote matching establish provenance, not semantic truth; the check is explicitly an interpretation, never a memory or relationship commit.

The same pass distinguishes sharing from explicit recall questions and action requests. Direct questions must be quoted from the current message; history cannot manufacture a question on the user's behalf. For sharing, unresolved side issues remain recorded but do not require unsolicited correction or demands for proof. Explicit questions still receive relevant evidence and honest uncertainty. This is a response-focus decision, not confirmation of all claims in the current message.

Citation validation is isolated per topic. An invalid source ID or quote removes that topic's proposed conclusion and leaves an explicit unknown, while independently verified topics remain usable. If all topics fail, the check is unavailable. Partial results never rewrite an invalid citation to a guessed source. Current activity uses the existing `linli.daily-life` projection only when `stale=false` and `current` is present; `last_observation`, rhythm and historical world facts cannot substitute for a live observation.

The check is shared by letters, IM/proactive replies, independent spoken text and song planning. It skips requests without historical evidence, uses one bounded model pass with low reasoning where supported, and respects the final input ceiling. Provider failure, invalid citations and insufficient capacity become explicit unavailable states without deleting the original window. There is no semantic retry loop. This adds a model request and latency when relevant evidence is present; it does not enable production reply review or a second response-generation loop.

The total reply budget includes the bounded check. Normal prepared replies retain the existing generation timeout; compatibility bridges reserve both preparation and generation time. Proactive planning itself does not run a recall check, while the resulting user-facing text/voice body does.

No new network service, generative query rewriting, emotion index, fact ledger, or cross-encoder model is installed. Time neighbors are bounded context expansion, not a general event-conflict graph. Automated tests cover route fusion, coverage after packing, fresh imports, source aliases, timestamps, failures, snapshot reuse, isolation, forgetting, and shared final requests across reply formats. Private local acceptance may use the user's corpus; repository fixtures remain synthetic. Capturing a final request or valid check JSON proves delivery and provenance, not that a live model will interpret every historical conflict correctly. Production reply review remains disabled.
