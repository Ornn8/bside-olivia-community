# 林离世界：生活节律与书信联动

生活节律与书信联动的设计和验收记录。原有 `private-world` 接口和数据库标识保留兼容，不要求迁移旧记录；安装包发布状态以 GitHub Release 为准。

## 不必专门进入世界页面聊天

正式信件回信完成后，生活提取读取双方最终正文，更新她的生活事项、共同约定及有依据的关系变化；后续回信按相关性取用这些状态。思考内容不作为事实。长期记忆保存用户事实与偏好，世界维护她的生活与共同事项，不另造一套用户档案。

## 作息与真实时间

默认使用上海时间，23:00 入睡、工作日 07:00 起床、周末 08:00 起床，另有用餐、专注、闲暇和收工时段。这是可调整的角色模拟起点，不是官方人设新增事实。

每次正式往来保留服务接收时间和最终回信完成时间。睡眠窗口内的通信按区间并集计时，不按信件数量乘固定时长。最后一次回信后安静满 30 分钟视为重新入睡；不足 30 分钟继续往来仍是同一轮清醒，达到边界再来信才是再次叫醒。重试和重复入库不会重复计算。

夜间清醒时间与反复醒来的额外负担共同影响疲劳；之后完整休息可逐步恢复。程序维护状态，模型负责自然表达和安排细节。这里不是人体医学预测器，不将一次熬夜直接推演成疾病或就医事实。没有来信不会凭空增加疲劳或惩罚关系。

## 持续不适、自我照顾和恢复

身体状态由多晚实际休息损失派生，区别于临时困倦。一晚短暂醒来不会自动变成生病；多晚持续损失足够多时，会进入身体不适状态，回信和页面读取同一份状态，她的练习与安排也应减少。随后完整的休息窗口逐步减轻负担，不会因为用户几天没上线反而恶化。

当前角色模拟参数：过去七天至少两晚清醒达到 90 分钟，且累计休息负担达到 240 分钟，进入不适；至少三晚且负担达到 360 分钟时，可以考虑门诊咨询。以上是可测试的故事连续性参数，不是医学结论。咨询只可成为待办计划，不因为日历跳过几天就自动变成已就诊，更不捏造诊断、检查或药物。她照顾自己，不以不适向用户索取陪伴或补偿。

恢复过程保留原事项，不把“打算休息后再练”写成“已经练完”。设置中的身体状态提示仅在不适或恢复中显示；最近一次分享另行标注，不冒充实时活动。

## 关系与适应

普通夜间闲聊导致她明确不适时，可通过既有关系账本记录摩擦；倾诉本身不被判为冲突，已有双方约定也应被尊重。临时疲劳与长期关系分开，不新增第二套好感分数。关系系统自身的去重、变化范围仍然适用。

作息适应参考过去七天至少三个不同夜晚的稳定通信，或用户明确陈述且有时区依据的通常入睡时间。它只提供相处时间参考，不把发信时间宣称成用户的实际睡眠。

当前模拟参数为每个活跃日最多调整 15 分钟，最大提前 60 分钟或推迟 120 分钟，并按现有信任、舒适和亲近状态缩放；入睡和起床一起移动以保留睡眠窗口。低关系状态逐步回归自身节奏，不立即跳变。新安排只作用于未来夜晚，不重算过去的疲劳。

### 发现并修复的失败

早期四封测试和第一次多日轮使用了错误的目录环境变量，复用了工作树旧测试记忆；其隔离验收结论已撤销，不计入上述成绩。随后干净测试曾出现将背景录音扩写为具体格言的情况，已收紧“已知背景不授权未知内容/引文”边界；同类复测不再出现该格言，仍不把有限样本等同于无幻觉保证。

旧边界轮第 4 封因上封记忆写入仍在途而被错误终结为 MEMORY_UNAVAILABLE。合版后等待已有操作落盘再继续一次，不关闭记忆、不另发重复 LLM 请求；同场景重新从正式寄信入口通过。

### 复现

[验收脚本](../tools/linli_world_acceptance.py) 仅接受环境变量 `OPENCODE_GO_API_KEY`，端点固定 OpenCode Go，不调用 DeepSeek 官方端点。使用已安装 Mem0 依赖的 Python，设置自己的 key 后运行：

```powershell
python tools/linli_world_acceptance.py --embedding-cache "<你的 BGE 模型缓存目录>" --scenario multiday
python tools/linli_world_acceptance.py --embedding-cache "<你的 BGE 模型缓存目录>" --scenario boundaries
```

另有 `basic` 和 `grounding` 场景。报告保存在独立输出目录；脚本使用真实模型，会消耗所配置服务的额度。测试成功不代表原生窗口或全部视频模型安装验收，最终安装包/补丁结果以发行说明为准。
