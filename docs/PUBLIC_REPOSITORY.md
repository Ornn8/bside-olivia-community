# Public repository boundary

这份文档定义“能公开维护的代码”和“只能留在本机/私有发布渠道的内容”。它不是原版资源授权，也不改变第三方项目的许可证。

## 可以公开

- 本地 HTTP、memory、media state 和 provider adapter 的源代码；
- 版本化契约、schema、合成 fixture 和不含真实内容的测试；
- 资源引用的逻辑 ID、来源说明、哈希校验接口和失败状态；
- 不包含机器路径、凭据、签名材料或私有媒体的开发文档。

## 不可以公开

- 原版安装目录、`feapp.dat`、提取后的前端/背景/角色素材；
- `CosyVoice/`、`LiveTalking/` 和其他第三方运行时、权重、缓存；
- 官方协议抓包、真实域名组合、签名盐、Basic/JWT/OSS 凭据和请求日志；
- `.evidence/`、生成音视频、真实 letter、用户数据库和任何本机绝对路径；
- 只在某台机器存在的 `D:/`、`F:/`、`E:/Python` 配置。

## 发布结构

建议将项目分成三个边界：

1. **公开源代码**：可在合成 fixture 上测试，不依赖官方安装或私有模型。
2. **本地集成配置**：由用户在本机填写 Steam 路径、模型路径和 provider 配置，不进 Git。
3. **补丁发布包**：只包含补丁器、校验器和本项目代码；不得重新分发官方游戏文件或第三方权重。

## 合入公开分支前

- 干净克隆可安装依赖并完成测试收集；
- 所有声明的 Python 模块、测试和入口都被 Git 跟踪；
- secret/path/large-file 扫描覆盖整个提交，而不只是当前 tracked 快照；
- 许可证、第三方 notices 和支持的 Python/Windows 版本已明确；
- CI 能在没有本机模型、官方文件和密钥的环境中通过基础测试；
- provider、官方资源和网络功能缺失时仍返回真实的不可用状态。

当前 `pyproject.toml` 只声明公开 HTTP/媒体状态基线；ASR、TTS、Live 和模型运行时仍属于实验模块，必须在模块自身完成依赖、入口和干净克隆测试后才能进入公开安装目标。
