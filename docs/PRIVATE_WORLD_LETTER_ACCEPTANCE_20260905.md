## 结论与边界

这不是所有模型语义均正确的承诺：模型仍偶尔附带没有充分依据的“确认过几次”表述；冲突分类在一次真实样例中返回空，不能据此宣称负向关系识别已通过。
本轮没有验收桌面原生界面、视频/GPU 或新的安装包，也没有覆盖个人安装数据。

## 路径与配置

- 从 `/toy/letter/send` 发送合成信件，由正式回复管线生成；不直接灌入回复、记忆或关系变化。
- 通过 `/toy/companion/memory` 和 `/toy/companion/private-world/life` 读取可见结果，并检查持久化和下一封模型输入。
- 只使用 OpenCode Go：`https://opencode.ai/zen/go/v1`，`deepseek-v4-flash`。主回信和 Mem0 配置均断言相同提供方和模型；未使用官方 DeepSeek key。
- 主回信保留思考，额外回信语义复核关闭。生活提取复用生产模型调用；只读取正文，不读取思考。
- Mem0 使用真实模型提取、BGE CPU 嵌入和隔离的本地 Qdrant。复用已有模型权重，没有使用个人信件或私人记忆数据库。
- 初始练琴近况为明确标记的合成场景；之后所有变化由正式发信流程触发。此项不等同于自然日刷新验收。

## 内容验收

- 口味：酸口、微辣、不吃香菜、不喜甜腻、温水、冰饮胃痛进入真实记忆；下一封及重启后点单追问能召回关键限制与原因。
- 承诺归属：她录琴、用户寄明信片分开保存；取消录音不取消用户的寄信计划。
- 时间与完成：用户寄出明信片后，仍区分“寄出”与“收到”；下一封状态盘点保持在途，没有误作已收到。
- 更正：最终回信承认旧计划表述有误；继续按“录音取消、不恢复”回应，没有把自主练琴等同于履行旧约定。
- 虚构经历：最终能识别大阪演出是用户明确编造的假设，不接成共同经历；关于交流次数的附加表述仍需改进。
- 关系：普通口味聊天不自动加分；明确收到支持、意愿被尊重以及修复样例有实际数值变化。未自动升级关系阶段或授予权限。冲突负向识别不能算已通过。

## 修复落点

1. 两层记忆超时恢复消费同一任务的迟到结果，不把另一封信的结果归给当前信。
2. 没有档案内容时回收空预算给当前记忆；仍保持整体上限和来源区分。
3. Windows 原子写入仅短暂重试共享占用错误，不删除旧文件或把其他写入失败视作成功。
4. 最近两封保留双方正文，更早只取最多两封相关用户原信，整体 2800 字符；不靠重复旧回信维护所谓一致性。
5. 已披露原信涉及的事项同步检索最新生活状态，生活上下文仍最多 1800 字符、两件相关事项。
6. 生活提取将既有状态与本封正文分开，不再提供旧证据引用供模型误抄；现有状态只用于识别变化。
7. 关系变化绑定已送达正式回信及双方原文证据，经既有账本与 reducer 幂等提交。

自动化回归覆盖以上连接点，但不替代上面的真实模型记录；每次实现变化仍须区分本地测试、真实模型观测、CI、安装包与人工体验。
