# Olivia 1.2.22

本次补丁修复 QQ / 微信即时聊天中两个会直接影响实际体验的问题：**断线积压消息被错误合并，表现得像吞消息**，以及**用户一句带时间前提的问题把林离的当前生活状态带偏**。

## 修复断线后“吞消息”

此前 QQ / 微信在短时间内收到多条消息时，会把它们合并成一个聊天回合。这个机制本来用于处理用户连续发出的短消息。

问题是，断线重连后，平台可能一次性把之前积压的历史消息全部送到 Olivia。旧逻辑只看“这些消息现在是不是一起到达”，不看“用户实际上是什么时候发送的”，因此可能把相隔几十分钟甚至几小时的消息错误合成一个回合。

1.2.22 开始：

- QQ 使用 OneBot 提供的原始消息时间判断是否属于同一个短消息 burst。
- 微信使用官方消息的 `create_time_ms` 判断。
- 只有真实发送时间足够接近的消息才会合并。
- 如果 11:23、12:03、13:04、13:23 的消息在重连后一起到达，它们会按真实发送时间拆成独立回合，不再只回复最后一个话题。
- 平台没有提供可用时间戳时，仍保留旧的到达时间合并兜底，避免破坏兼容性。

系统同时会把“这是延迟到达的旧消息”明确告诉回复生成层，避免把历史积压误认为用户刚刚发来。

## 修复当前时间与生活状态错乱

此前用户例如在北京时间 13:23 问“吃晚饭了吗”，模型有可能顺着问题回答“刚吃完晚饭”，随后生活提取器又把这句话保存成“林离当前生活状态”，于是世界页面会出现 13 点多“晚饭已经收尾”这样的错误状态。

1.2.22 增加了多层保护：

- 当前时间始终以林离所在上海的北京时间为准，用户的问题不能改写当前钟点。
- 用户问早餐、午饭、晚饭、睡觉等，只是问题本身，不是当前时间证据。
- 即时聊天会区分 `decision_now`、用户原始发送时间和实际收到时间；延迟消息不能当作现在发生。
- 回复质量检查会核对当前餐次/活动是否与当前时间和世界作息一致。
- 世界状态增加确定性校验：明显不合时段的“刚吃完早餐/午饭/晚饭”“晚饭已经收尾”等当前事实不会被发布。

为了处理已经被旧版本写进去的错误状态，1.2.22 还会在读取时过滤这类明显不可能的旧餐次近况，因此升级后不需要手动删除数据库。

## 回归测试

新增覆盖：

- QQ 重连后同时收到两条实际相隔一小时的消息，必须拆成两个回合。
- 微信同一轮 poll 收到实际相隔一小时的历史消息，必须拆开。
- 原本没有平台时间戳的短 burst 仍保持兼容行为。
- 北京时间 13:32 的“晚饭已经彻底收尾”不能成为当前世界状态。
- 北京时间 18:32 的同类晚饭状态仍然可以正常记录。
- 旧版本已经持久化的错误餐次当前状态在升级后自动从当前视图中隐藏。
