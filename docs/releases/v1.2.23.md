# Olivia 1.2.23

本次补丁针对 QQ / 微信作为长期常驻聊天通道时的断连问题，补齐连接守护、重连状态和登录失效处理。

## 微信长期连接

此前微信连续网络失败超过 6 次后，当前 transport 会退出，再由外层重新启动，网络波动较长时可能出现明显空窗。

1.2.23 开始：

- 临时网络错误不再因为“连续失败次数过多”而停止监听；
- 使用有上限的指数退避持续重试，最长单次等待 30 秒；
- 一旦轮询恢复成功，立刻回到 `CONNECTED`；
- HTTP 401 / 403 明确识别为登录授权失效，状态变成 `AUTH_REQUIRED`，设置页提示重新扫码，不再拿失效凭据无限重连。

## QQ / NapCat 长期连接

QQ 侧补上两层恢复：

- OneBot 每次真实登录成功后都会清零历史重连退避。即使之前断过很多次，之后再次断线也会从快速重连重新开始，不会永久停留在 30 秒级退避。
- 如果 NapCat 返回 QQ 已掉登录，状态会变成 `AUTH_REQUIRED`。Olivia 会继续保留监听恢复循环，用户重新登录 NapCat 后可以自动重新接上，不要求重启 Olivia。
- 对 Olivia 一键管理的 NapCat 增加 watchdog：如果 Olivia 启动的 NapCat 进程退出，同时本机 OneBot 不可用，会自动重新拉起组件。

## 更准确的在线状态

原先 `LISTENING` 只能说明监听任务还活着，不能证明平台真的连通。

现在状态细分为：

- `CONNECTING`：正在建立连接；
- `CONNECTED`：最近一次真实 QQ / 微信通信正常；
- `RECONNECTING`：网络或本地协议端暂时断开，正在恢复；
- `AUTH_REQUIRED`：登录凭据/QQ 登录已失效，需要用户重新登录；
- `STOPPED`：监听已停止。

设置页会显示这些状态，并在连接或重连期间自动刷新。同时只保存一个不含聊天内容、账号或凭据的 `last_seen_at` 健康时间。

主动 QQ / 微信消息也改为只有 transport 真正处于 `CONNECTED` 时才允许发送，不再因为后台任务还活着就误认为通道在线。

## 回归测试

新增和更新测试覆盖：

- 微信连续超过 6 次网络失败后仍能自动恢复；
- 微信 401 授权失效进入 `AUTH_REQUIRED`；
- QQ 断线后重新登录会恢复 `CONNECTED` 并重置重连节奏；
- QQ 掉登录时进入 `AUTH_REQUIRED`；
- Olivia 管理的 NapCat 进程退出后 watchdog 自动重新启动；
- 原有消息持久化、离线 Windows 安装和完整公共测试继续通过。
