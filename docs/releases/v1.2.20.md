# Olivia 1.2.20

本次更新补上了信箱与 QQ / 微信之间的衔接：信箱仍然是低即时性的长内容渠道，QQ / 微信仍然是即时聊天渠道，但用户在即时聊天中出现时，林离现在能意识到“之前那封信可能还没被看到”。

## 信箱 × QQ / 微信

- 如果林离已经主动发出一封信，并且这封信仍然是**未读**状态，之后用户主动在 QQ 或微信聊天时，林离会在这一次正常回复里顺带提醒一次“信箱里有封信”。
- 这个提醒只是告诉用户信件存在，不要求用户回复，也不会把“没有回信”理解成冷落、拒绝或关系变化。
- 提醒不会单独触发一条新的主动 QQ / 微信消息。只有用户本来就在即时聊天中发来消息时，才会附带在正常回复里，因此不会出现“刚发完信又马上追到微信催”的行为。
- 同一封信只提醒一次，而且 QQ / 微信共享这个状态：如果已经在 QQ 提醒过，之后切到微信不会再重复提醒；反过来也一样。
- 只有即时消息已经被平台确认送达后，系统才会把这封信标记为“已在即时聊天提醒过”。如果发送失败或处于未知状态，不会提前写成已提醒。
- 如果用户已经打开信箱并读过这封信，则不会再出现提醒。
- 联系方式邀请信不参与这套提醒，避免用户已经完成 QQ / 微信绑定后又收到过期的“去看联系方式邀请”提示。

当前默认提醒语气保持低压力，例如：“对了，我之前往信箱里放了封信，你有空的时候再看看就好。”重点是提醒“有东西在那里”，而不是提醒“你应该回复”。

## 原有调度保持不变

- QQ 和微信继续共享同一个即时聊天调度，最后活跃的即时渠道仍然是后续主动聊天的目标。
- 信箱继续使用自己的主动来信节奏；已经存在未读主动信时，不会继续堆新的主动信。
- 本次更新没有把“信箱未读”变成 QQ / 微信的主动发送理由，也没有让信箱与即时聊天互相阻塞。

## 稳定性

新增回归覆盖：最新未读主动信选择、已读信/联系方式邀请/已经提醒过的信件排除、禁止单独主动 IM 提醒、QQ→微信跨渠道只提醒一次、平台送达确认后才落状态、持久化失败回滚，以及与现有个人聊天消费者顺序的兼容。

功能 PR 在合并前通过 Windows / Python 3.12 全量 `public-smoke`、仓库 hardening、whitespace 检查以及 Windows 离线安装器构建。

## 更新方式

从 **1.2.19** 更新到 **1.2.20** 后，完全退出 Olivia 再重新打开即可。已有信箱内容和 QQ / 微信绑定不会因为本次更新被重置。
