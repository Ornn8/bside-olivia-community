# Token 用量与费用控制

成本改动保持模型与思考档位，记录实际用量并减少无效调用。并行的人格与关系改动另见
`relationship-expression-validation.md`，不以降档或删掉人格来换取费用下降。

## 用量记录

应用设置 `OLIVIA_LOCAL_DATA_ROOT` 时，网关与 Mem0 将聚合计数保存到
`<data>/diagnostics/token-usage.sqlite3`。按 UTC 日期、用途和网络结果累计，保留 90 天。
不保存信件、思考内容、请求 ID、密钥、URL 或用户标识。统计写入失败不阻止回信或记忆写入。
数据库被占用或不可写时，会记录固定日志码 `TOKEN_USAGE_WRITE_FAILED`；出现该码的时段统计可能不完整。

- `attempts` 是调用次数，网关重试逐次记录；Mem0 SDK 内部的透明网络重试无法从该包装层逐次观测。
- `input_tokens`、`output_tokens`、`cached_tokens`、`uncached_tokens`、`reasoning_tokens` 来自服务商 usage。
- 每项有 `total` 和 `samples`；`samples` 小于调用次数表示有缺失值，不能当作零费用。
- `reasoning_tokens` 属于输出 token 的细分，不再加到 `output_tokens` 上。
- `response` 表示拿到了响应，不保证它通过结构校验或已交付；截断、无效正文仍可能计费。
- 本轮不估算货币金额，混用模型/平台、SDK 内部重试和缺失 usage 时，账单仍以服务商为准。
- 仅 DeepSeek 官方 Chat Completions 主动请求流式 usage；其他兼容平台保留原协议，能读取的 usage 仍会记录。

在应用后端目录、设置好应用数据目录环境变量后运行：

```powershell
python -m runtime.diagnostics.usage_metrics
```

输出仅包含上述聚合计数。该数据库不会自动上传。

## 缓存与后台止损

缓存布局不改声明的权限层级与内容，将固定声明排在动态上下文之前；变化的时钟移到单独必留的 `runtime_time`。
样例、关系、世界、历史仍逐次生成，现有来源标签和预算裁剪优先级保留，全局预算不变。
这增加可复用的固定前缀，不保证每次服务端都命中缓存。

世界日常刷新失败退避跨重启保存，同一个六小时时间块达到失败上限后暂停，下一时间块可恢复；
不更改正常记忆提取或正文的思考档位。主动发信已有的小时退避继续保留。
路由判断另加最多 128 项、五分钟有效的进程内成功结果缓存；键由来信内容和完整路由上下文/视频设置摘要组成，
更换网关实例即失效。每次仍重新检查媒体可用性，失败结果不缓存，不缓存回复正文。
该缓存覆盖顺序重复预览，不承诺合并同时到达的请求。

## 验证与下一轮实验

自动测试用本地假 HTTP 服务与假 SDK 验证：重试次数、结束事件后的 usage、截断结果计数、
缺失用量、隐私字段丢弃，以及统计故障不影响生成。完整正文结束后，不能仅因用量尾事件丢失而重复生成。

下一轮使用同一组隔离来信与冻结的记忆/世界状态，分别记录冷缓存与连续调用结果。
比较每封总调用数、已报告输出/思考 token、缓存命中比例及缺失样本；同时比较记忆事实、世界一致性和文风。
缓存实验至少连续三次，不通过预热空请求制造节省，也不把缓存省下的输入比例当成总费用降幅。
没有真实 usage 对照前，不承诺费用下降百分比、不降低核心回信思考、不压缩人格或删去必要记忆。

## Low / high 完整记忆链路对照（2026-09-10）

先做三个后台提示词小样本，随后使用真实安装 Mem0、本地 BGE、产品适配器和隔离 Qdrant/SQLite，
验证搬家/取消复诊、撤回称呼/纠正关系两组案例，每档各重复两次。后者八次提取都单次通过，
新纠正均成功存储并召回；没有截断或校验重试。各档输入 35662、缓存命中 25472 token 相同，
low/high 输出分别 1848/2822 token，按执行时官方高峰价估算约 0.0362/0.0440 元。
本轮 low 估算费用少 17.7%，不作为普遍节省率或真实用户质量承诺。

代码中的官方 Flash 记忆提取原本已用 low，保持现状；先前“记忆暂留 high”的建议误述了当前配置。
四组主动信首次与重复提交验证均零记忆提取调用，原文及林离来源标记完整。
这不意味着主动信生成或世界状态写入没有模型调用。

完整 Mem0 输入约 8900 token/次，主要是上游固定 system 规则与示例；重复调用最高命中 8704 token。
旧事实仍按历史保留，新纠正可以召回。下一步先用离线短查询与上下文裁剪回放检查旧事实单独入场的风险，
再评估重复提示词的精简收益；不因提示词长而直接删除约束。此次没有改生产思考档位或人格资产。

## 验证收尾与建议顺序（2026-09-10）

追加 96 个离线短查询/预算回放：2400、1200 字各 24/24 保留目标新事实；800 字时 16/24 只剩旧说法。
原因包含旧事实在短查询中排名靠前，以及新旧纠正未作为一个选择单元。只把文本截断分支改为停止的
隔离候选没有改善，已否决。上游模型输出的 linked_memory_ids 当前未在同步事实记录构建时用于纠正关联，
不能直接依赖这个字段。未修改生产裁剪代码。

世界消费入口补充 low/high 各六次：12 次全部落盘，14 次网络（含两次原有行为核验），无纠错重试。
本轮同输入/同缓存条件下 low 比 high 估算费用少 44.1%；当前 Flash 世界入口实际使用 max，不能把这个
比例宣称为相对当前配置或整封信的节省率。主动邀请保持 awaiting_user，边界撤回引用正确映射。

四组人格/记忆/世界组合各一次真实生成，组合组答对新住址与取消约定，但仍增加了未经证实的
“换过之后就没再改口”。不是完整产品审核或文风验收。24 个预算装配显示，默认 30000 字时这批
上下文完整，降低到 16000 时组合组的记忆整体被裁；作息规则与状态始终同步保留或裁掉。

方案顺序：先交付已有用量/缓存/退避改动；维持记忆 low，单独调整世界任务档位且保留核验；
修复旧事实与新纠正的呈现，再考虑减少重复来源表示；暂不降低全局预算、不重写人格或大幅删 Mem0 示例。
实验详细证据与实施验收门槛保存在本地 `.evidence/cost-final-validation-20260910/PLAN.md`，不随公开包发布。

## 纠正事实呈现修复

预算紧张且当前 Mem0 旧格式放不下足够完整事实时，使用共享来源表的 JSON 表示：
`observations` 保存来源与观察时间，`facts` 通过 `observation` 索引引用它，并保留完整 citation 与原文。
只有新表示至少保留两条、且比旧表示保留更多完整事实时才替换；引用、特殊字符转义和总预算约束保持。
Archive 仍走原有表示。没有重排检索、推断新事实覆盖旧事实、写库或增加模型调用。

同一批 96 个离线回放中，旧说法单独入场从 16 降为 0，目标新事实保留从 53 增为 72，
没有减少其他已显示事实；600 字极小预算仍返回空上下文。该修复解决已检索到纠正但呈现容量不足的案例，
不代表实现了通用纠正关系，也不能找回未被检索到的事实。未降低默认 2400 字预算。

## 固定前缀实测与生产接线补充（2026-09-10）

在人格参与方式调整前冻结的布局对照中，同组四封不同来信/分钟的公共前缀从 5793 字符增至 13013 字符。
每个字段仍使用本封的时间、关系和世界快照，没有复用旧的正文或状态。
官方 Flash、high、10000 上限，每布局连续四次，后面三次旧布局命中均为 1920 token，新布局均为 4480 token；
大约 35%/82% 的输入命中比例只描述这批后三次调用。第一次旧布局已有缓存、新布局较冷，不能视为对称冷启动。
新布局输出/思考 token 在本小样本反而更多，不能把输入节省比例作为整封费用降幅。

官方说明缓存按前缀匹配、建设需要时间且 best-effort；本轮用实际返回的 usage 验证，没有增加空请求预热。
来源：https://api-docs.deepseek.com/guides/kv_cache/

关系表达接线每封不增加模型调用。已完成正文后的流式 usage 尾事件中断不会触发重新生成；
世界退避覆盖 TimeoutError（它是 OSError 子类），不需要新增重复异常分支。
