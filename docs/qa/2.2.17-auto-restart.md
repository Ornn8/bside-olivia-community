## 行为

- 更新、手动校验安装、回滚成功后显示版本和五秒倒计时，可选择“稍后手动重启”。接口失败时保留手动重启提示。
- `POST /toy/update/restart` 使用现有来源、确认头和会话校验；本进程成功更新或回滚前返回 409，成功启动助手后返回 202，一次性消费重启资格。失败启动助手时可以重试。
- 助手仍在 `launcher/version_launcher.py`，通过 Windows 进程创建服务使用内置 `pythonw.exe`、`DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 和隐藏窗口启动。这样不需要修改旧启动器禁止子进程脱离的 Job Object，也不会被旧启动器退出时连带结束。
- 助手固定旧进程快照，验证可执行文件/命令行的安装目录边界和进程创建时间，保留进程句柄，排除自身。先请求窗口关闭，等待最多 20 秒，再只结束仍存活的这些旧进程。新启动后不再扫描或终止进程。
- 后端在发送完 202 后请求 aiohttp 正常退出。助手通过原来的 `version_launcher.py ... start` 入口启动激活版本，等待后端和客户端启动记录；失败写入错误码并显示系统提示框。
- 不改修复工具、`proactive-login` 或原有启动器的 Job Object 拥有关系。

## 必须由 Claude 决定的首次升级边界

**未修改的 2.2.16 无法在首次安装此补丁后自动重启。** 补丁切换磁盘上的激活版本，不会替换旧进程已加载的界面脚本和后端路由。实测旧进程对新接口返回 501。必须先手动启动一次 2.2.17，之后才具备本 PR 的自动重启能力。

这不是“原版 2.2.16 → 2.2.17 全程无人操作”验收通过。需要决定接受一次性手动启动的引导，还是另立任务为旧版本提供引导程序。回滚至不含本功能的版本后，再次更新也受同一限制。PR 保持 Draft，不合并、不发布。

## 本机独立安装验收

使用既有离线安装验收方式，在 F 盘新建 110 字符、包含中文和空格的安装目录。使用独立数据和端口，不使用现有正式安装。

| 场景 | 实际结果 |
| --- | --- |
| 原版 2.2.16 安装本分支 2.2.17 补丁 | 激活切换成功；旧进程缺少新接口，不能自动重启，明确保留上述限制 |
| 手动启动一次 2.2.17 后重新安装补丁 | 202；旧启动器退出；自动启动后出现 `backend_ready`、`client_start`、`update_restart_ready` |
| 2.2.17 回滚至原版 2.2.16 | 202；自动启动后运行版本为 2.2.16，出现 `backend_ready` |
| 2.2.17 更新至同源码的仅验收版本 `2.2.17-restart-qa` | 自动重启；运行版本、激活清单和补丁 manifest 哈希一致 |
| 仅验收版本回滚至 2.2.17 | 自动重启成功 |
| 激活版本启动文件临时缺失 | 202 后启动失败；记录 `UPDATE_COMPONENT_UNAVAILABLE` 和 `UPDATE_RESTART_START_FAILED`；实际显示“Olivia 自动重启失败，请手动打开”系统提示框并截图核验 |
| 清理 | 已确认该安装没有遗留进程，删除整个独立测试安装，保留脱敏日志和截图 |

实际客户端关闭请求没有让整个旧进程树及时退出，上述重启走到了 20 秒超时后的限定范围清理。新版本启动在旧进程停止之后，没有终止新进程。此处是本机独立安装的进程和启动验收，不代表账户服务、媒体功能或其他设备验收。

## 自动化验证

- 最终相关测试：176 passed，覆盖接口、更新包、启动器、倒计时取消/失败回退、进程归属、等待超时、失败提示和日志。
- `client/baseline_hardening_scan.py --mode all`：PASS，matches=0。
- 全量范围采用仓库 `pytest.ini` 的默认 testpaths 和 `not experimental` 选择；最终源码冻结后分四组覆盖收集到的全部 8291 个用例，每组使用独立临时目录。原始结果：8264 passed、19 failed、8 skipped。
- 19 项失败在规定的 `.evidence` 目录复核后为 11 passed、8 failed；其中 10 项原始失败由验收脚本将临时目录置于外部 artifact 目录造成，另 1 项 Mem0 并发用例复核通过。相关目录边界测试整组重跑为 24 passed。
- 最终剩余 8 项失败与下面 main 默认环境复核的 8 项完全一致；没有把它们计为全量通过，也没有修改无关记忆代码或系统环境来隐藏失败。
- 源码提交的 GitHub 离线 Windows 安装器构建通过。交付时 Windows smoke CI 尚在运行，与本地验证分别记录。

### main 失败对照

main 原始全量运行：8178 passed、20 failed、8 skipped。失败复核时，将临时目录恢复到测试要求的仓库 `.evidence` 内，20 项中 12 项通过，8 项仍失败。不能把临时目录不符合测试约定造成的报错算作产品缺陷。

默认本机环境下可复现的 main 失败：

- `tests/memory/test_mem0_memory.py::test_exchange_write_timeout_keeps_one_daemon_and_fails_closed_on_retry`：预期后台写入已开始的事件未置位。
- `tests/memory/test_olivia_memory_launcher.py::test_dragged_folder_starts_tool_and_remembers_exact_path` 的 `root-normal`、`root-bang`、`runtime-normal`、`runtime-bang`、`interpreter-normal`、`interpreter-bang` 六个参数组合。
- 同文件 `test_candidate_root_still_finds_deeper_runtime`。

后七项的错误为 cmd 找不到 `run.cmd`。本机设置了 `NoDefaultCurrentDirectoryInExePath`；仅在验证子进程中移除该变量后，这七项全部通过，没有修改系统或用户环境。另两项原始全量中的关系补录/慢响应测试在复核时通过，保留原始失败记录，不将一次通过视为消除时序波动。

进一步用同一组 9 个记忆用例并行对照 main、2.2.16 基线和本分支，三者均为 3 failed、6 passed，失败节点完全一致：

- 上述 Mem0 写入超时测试。
- `tests/memory/test_mem0_memory.py::test_concurrent_exchange_serializes_exact_deduplication_and_write`。
- `tests/memory/test_relationship_continuity.py::test_shared_prompt_keeps_original_identity_across_models_after_tail_expires[text_letter]`。

这组对照用于区分继承问题与本次改动，不修改无关记忆实现。
