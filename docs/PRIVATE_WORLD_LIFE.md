# 林离的生活：私人世界第一版

私人世界以林离为中心：用户能看见她的生活，也能看见自己的参与留下的变化。
它不是第二套用户摘要库，也不是显示好感度分数的控制台。

## 用户入口

设置 → 本地陪伴 → 私人世界，包含：

- 此刻的林离：已保存的地点、活动和一句公开近况；过期记录明确标为最近近况。
- 最近在忙：默认最多三条简短事项，展开才读详情，其余及已结束事项折叠。
- 生活片段：默认最近三条，不重复“此刻”的同一条记录；历史按每页八条翻阅，不删除旧记录。
- 与你有关：默认最多两条未结束事项，记录信件中的推荐、约定和参与，不是用户履历列表。
- 你们的关系：按需展开，读取原有关系阶段及熟悉、信任、自在、亲近、紧张程度，不展示隐藏原始分数。

“围绕这件事写信”展开包含原近况和时间的开头；用户复制到原信箱继续写，不自动寄信。
页面与回信共用同一份持久状态。原关系状态接口仍保留兼容，但不再作为主页内容。

## 运行方式

使用当前配置的大模型，不增加 GPU 模型。读取和切换页面不等待模型生成。
启动或打开页面时，近况超过六小时才尝试推进；同一时段、重复打开和并发刷新复用记录。
离线期间不运行：下次使用时只生成当前近况与少量衔接，不伪造逐日活动流水账。
失败时保留旧内容并显示更新失败，短暂退避后可重试，不把失败说成“已经更新”。

生成依据与回信相同的运行时人格资产，只取居所、当前学业阶段、阅读、练琴、口味等相关声明。
新日常是角色生活续写，不冒充官方原剧情；自动推进不能修改 shared 事项。

正式回信完成后，后台读取用户来信与最终回信；不读取思考、TTS、歌词编排或失败草稿。
每次更新需有对应说话人的连续原文证据；对普通问候可不产生任何生活事件。
明确的未来承诺保存为待履行事项，不因尚未完成而遗漏。格式或原文校验失败时，返回错误原因让同一个模型纠正一次，失败不部分保存。
后台生活调用沿用模型配置中的思考等待时间，不强行关闭思考，也不强制最高思考档位；页面异步读取，模型慢时仍能阅读旧记录。
若回信明确给出“现在的活动”，该原文会覆盖旧的当前近况，避免页面和回信各说各话。
任务未完成便退出时，下一次启动重试待处理信件；单个更新失败不撤销已完成的回信。

## 数据分工与一致性

- Mem0：继续负责用户明确提供的事实、偏好和长期检索；本改动不改写它的提取逻辑。
- 原始信件：交流的原始依据，按 `reply:<letter_id>:<revision>` 关联。
- 私人世界生活：公开近况、持续事项、共同事项及其来源；不复制一般用户偏好。
- 关系系统：已有关系权限和边界保持原实现，不由生活生成顺带升级。

生活 SQLite 位于当前用户私人世界数据库旁的 `daily_life.sqlite3`；不同用户沿用既有隔离路径。
不修改现有关系数据库 schema，不迁移/清空个人记忆，不读取私有语料做初始化。
已发布片段保留；较晚到达的旧信不倒退当前事项。相同来源内容冲突不被默认为重复成功。
读取回信上下文最多 1800 字符，先取当前公开近况，再取最多两件相关事项，不灌入完整生活日志。
召回从所有已保存事项检索，不受页面条数上限限制；相关共同约定优先，较新的取消状态覆盖旧近况中的承诺，无关问候不填充随机事项。
历史采用时间及来源游标分页，翻页期间新记录进入首页不会导致旧页重复或漏项。

## 第一版边界

已接通：持久状态、按需时间推进、正式回信后的更新、页面展示、下一封信的上下文。
没有接入：自动生成生活图片/音视频、后台永久运行、主动通知、旧信自动回填、新的关系晋级规则。
目前不把每条日常再写进 Mem0；因此没有新增“删 Mem0 后又从生活摘要回灌”的路径。
删除/纠正 Mem0 不会抹除原信和角色生活，仍遵循现有记忆管理契约。未来跨来源纠正需要独立定义，不能悄悄扩大清空范围。
原文匹配验证的是证据出处，不能证明模型的每个语义判断都正确；真实模型质量需单独验收。

### 基于信件的关系变化

`CANONICAL_REPLY_DELIVERED` 仍然只登记送达，不按发信次数增加好感。
生活提取复用同一次模型调用，另可提取“明确收到支持、尊重意愿、冲突、修复”之一，普通聊天默认无变化。
必须同时引用来信和最终回信的连续原文，保存时绑定双方正文摘要，提交关系账本时再校验已送达回信的 SHA-256。
恢复任务读取已保存的证据，不重做模型分析；同一送达只应用一次，同类正向互动沿用原有语义去重与成长约束。
变化通过原有 reducer 更新信任、自在、熟悉或紧张，不自动授予昵称、身体接触、居所访问或关系阶段。
生活页面不展示这段内部分类材料；关系部分仍使用原有行为投影。

### 回信与记忆链路

回信的额外语义复核默认不启用；主回信模型仍保留思考，模型复核可显式配置开启。
长期记忆没有命中档案时，空闲的档案预算让给当前记忆，不再无条件浪费一半上下文。
另从已完成的原信中保留最近两封双方正文及最多两封更早的用户相关来信，总计最多 2800 字符，整段按时间正序呈现；不把更早回信中的猜测反复作为召回依据。
只读用户来信与最终回信，不包含思考、草稿、失败信件或当前正在生成的信件；原文过长时整段跳过，不截掉末尾否定。
这些历史仍是参考资料，不是系统指令；旧回信不能自动成为角色的真实经历。原信窗口不新建第二份记忆库。
历史窗口提到旧事项时，同步在原有生活上下文预算内检索其最新状态，优先回答当前问题；不再仅因旧信提到一个计划就沿用过期状态。
用户的明确行动、更正、撤回优先于回信中的猜测；提取器不能把个人练习误作恢复共同承诺。有限历史窗口不能用于推断提问次数或声称过去答案始终一致。
Mem0 后台写入超时后会领取原任务的迟到结果，避免永久卡住或重复写入；信箱原子保存会短暂重试 Windows 共享占用。

## 验证

聚焦测试覆盖：刷新/重启稳定、过期不自动完成、原文证据与说话人、重复来源与内容冲突、
日常生成不能完成共同事项、模型失败保留旧内容、当前回信覆盖旧近况、真实 HTTP 路由、
最终回信到持久生活到下次 Persona 提示词、旧私人世界和设置页回归。
浏览器检查使用真实设置页脚本和本地 HTTP 接口，合成数据，不调用个人模型或使用真实信件。
