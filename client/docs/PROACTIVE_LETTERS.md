# 本地主动来信

主动来信默认关闭。原生设置提供主动来信、允许语音、登录 Windows 后检查主动来信三个开关。登录检查同样默认关闭，不创建云端任务。

## 两阶段运行

主程序把已有往来和用户提出的待办事项投影成不含正文的机会快照。后台登录检查器每五分钟读取快照，只保存待写意图，不启动 HTTP 服务、界面、LLM 或语音模型，不写信箱、Mem0 或 PrivateWorld。电脑关机或休眠期间不执行、不追补遗漏次数。

应用启动后，有待写意图时先等待运行时初始化；没有待写意图时使用五分钟启动窗口。生成前重新检查最新往来、意图有效期、未读主动信、当前任务、记忆可用性、当地 09:00–22:00 时段及滚动 24 小时最多三封的限制。已有话题不强制发信，模型可以选择暂缓。付费判断前持久化一小时退避，避免重启反复调用。

机会记录不是固定提示词或已经发生的交流。当前实现以最近一次已完成的用户来信及用户提出的未完成事项为候选，不将林离自己刚写出的日常变化自动转成下一封信的触发器。它不推断诸如面试成功等未报告的结果，也不虚构离线生活。

## 生成与投递

判断机会时不锁发送；实际撰写正文、生成语音和投递期间锁住发送，后端也拒绝冲突请求。用户可以继续编辑草稿。生成使用现有模型、人格、记忆召回及世界状态，不新增人格资产。

主动信复用原生信箱详情，不能在详情直接回信。用户仍从正常写信入口发信。语音不自动播放；语音失败时交付已有文字，文字与语音合计只占一封额度。

未完成的主动信在信箱中不可见。只有已发布的 `COMPLETED` 行才能进入记忆投递 outbox；失败和取消不占额度。意图、草稿和实际投递是不同状态。

## 记忆与世界

- 原信保存 `origin=proactive`、空 `content`、完整 `reply_text`、实际发布时间及 `reply:<id>:<revision>` 来源；不伪造用户发言。
- Mem0 保存带来源的林离单方原文，不把原文再次改写成用户事实；近期上下文也能直接召回正文。
- DailyLife 可提取林离自己的进展、承诺和边界，并保存逐字证据。共同邀约只能处于 `awaiting_user`。
- 单方主动信不能生成关系互动事件、用户行为或用户作息，不能增加双方已确认的亲密关系。
- 语音交付在实际文件完成且信件发布之后另记一次交付事件；它不是又一封信，也不证明对方听过。

## 文件与恢复

主程序拥有 `data/proactive/context.json`、`settings.json`、`schedule.json`；后台只更新 `pending.json`。这些都是原子替换的小型 JSON 文件。信箱仍使用既有 `state.json`，后台不改它。每次准备和正式生成都重新校验来源，后台旧意图没有投递权限。

Windows 登录入口使用现有安装的 `pythonw.exe` 与版本启动器，以命名 mutex 防止重复后台进程。安装路径不完整时拒绝启用登录启动，不写失效的注册项。

旧升级器可能只切换 active backend 而不更新稳定启动器。因此启用或启动后台时先验证当前 active backend，再原子更新稳定启动器；旧安装也能首次启用新入口。关闭登录检查后扫描器退出，卸载时禁用扫描、清理专属登录项并停止所属进程，保留用户信件数据。

验证使用隔离临时数据与模拟模型。合成回归不等于真实原生客户端点击、语音试听或真实模型文风验收；这些需在安装包上另行验收。

2026-09-10 开发验证：记忆/PrivateWorld/近期往来及主动机会回归 873 项通过；HTTP 回归 546 项通过、1 项 deselected。后续主动投递专项同时覆盖语音成功/失败、判断时收到用户新信、生成锁、已读落盘、世界提交失败后重试和主动上下文故障不阻断普通生命周期。

收尾聚焦回归 70 项通过，包含后台启停、旧升级器迁移、卸载、原生投影和设置/发送守卫。已在合法原版资源的隔离副本上应用补丁，重复应用返回 `ALREADY_PATCHED`，完整 main JavaScript 通过 `node --check`；原版资源不进入 Git。主动信复用 Collection 的 welcome-paper 分支，动态音频参数随所选信件切换，不新增详情路由。

发布顺序仍遵循现有普通回信链路：先持久化可见的 canonical 信件，再提交可恢复的世界事件。世界暂时不可用时保留 `PENDING`，恢复后按相同 delivery ID 幂等提交。不能为了等待世界整理而提前把未投递草稿写成世界事实；原文记忆与派生世界整理的恢复状态相互独立。
