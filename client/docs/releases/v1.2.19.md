# Olivia 1.2.19

本次更新把 QQ / 微信联系方式绑定流程继续收拢成普通用户可操作的界面，并修复“已经收到并接受联系方式邀约，但设置页仍然没有绑定入口”的流程断点。

## 联系方式邀约

- 只要林离的联系方式邀约已经成功送达，设置页现在会直接显示“微信 / QQ / 两个都要”的选择，不再要求用户额外寄一封信并在正文里再次写出“微信”或“QQ”。
- 选择 **微信** 后会立即进入现有二维码绑定流程；选择 **QQ** 后直接打开 QQ 本地组件流程；选择 **两个都要** 会同时解锁两条通道。
- 这个选择会写入现有联系方式邀约记录并持久化；之后如果用户在来信里明确选择其他渠道、暂缓或拒绝，仍然以用户最新的明确表达为准。

## QQ 一键本地组件

- QQ 设置页新增 Olivia 管理的一键安装入口。普通用户不再需要手动理解 OneBot WebSocket、地址和 Token。
- Olivia 使用 NapCatQQ `v4.18.28` 的 Windows Node 自包含发行包 `NapCat.Shell.Windows.Node.zip`。用户点击安装后，Olivia 从上游发布页下载固定版本并验证 SHA-256，校验通过后解压到本机 Olivia 数据目录。
- NapCat 二进制**不会被重新打包进 Olivia 的 ZIP / `.oliviapatch`**。这是为了保持第三方许可证边界清晰；功能上对用户表现为设置页中的一键安装组件。
- Olivia 会为该组件使用独立工作目录，自动生成只监听 `127.0.0.1:3001` 的 OneBot WebSocket 配置和随机 Token，并把 NapCat WebUI 限定在 `127.0.0.1`。
- 点击“启动并登录 QQ”后，Olivia 会启动本地 NapCat 并打开其本机登录页。QQ 登录完成后，用户只需要填写自己的 QQ 号；机器人 QQ 会通过 `get_login_info` 自动读取。
- 高级用户仍可以展开“连接已有 NapCat / OneBot”，继续使用自己的本地实例。

## 安全与许可

- NapCat 下载地址和 SHA-256 固定到 `v4.18.28`；下载后的 ZIP 在解压前校验完整性，并拒绝路径穿越、符号链接和异常体积。
- 管理模式的 OneBot 和 WebUI 都只监听本机回环地址，不向局域网或公网开放。
- Olivia 的 QQ 配置不会写入明文 OneBot Token；Olivia 自己保存的 Token 副本继续使用 Windows DPAPI。NapCat 自身的 OneBot 配置必须持有它提供服务所需的 Token。
- NapCat 采用其自己的 `Limited Redistribution License for NapCat`，其中包含非商业使用限制。Olivia 不修改或重新授权 NapCat；使用者需要确保自己的用途符合该许可证。

## 更新方式

下载 **Olivia-1.2.19.zip**，在“本地陪伴 → 补丁更新”中选择该 ZIP；也可以使用同版本 `.oliviapatch`。更新完成后完全退出 Olivia 并重新打开，确认运行版本为 **1.2.19**。

如果你之前已经收到联系方式邀约但设置页一直提示“还没有选择聊天渠道”，升级后不需要重新触发邀约，直接打开设置页即可看到渠道选择入口。

## 验证

本次改动通过 Windows / Python 3.12 `public-smoke`、仓库 hardening、whitespace 检查和 Windows 离线安装器构建。新增回归覆盖：已完成邀约直接选渠道、NapCat 固定来源与哈希、恶意 ZIP 路径拒绝、独立工作目录、OneBot / WebUI 回环绑定、受管 QQ 登录与账号读取、组件错误脱敏以及安装后自动发现。

云服务版本仍独立维护，本补丁仅更新本地版本。
