# 运行与故障统计

运行统计默认开启，设置页面不显示开关或统计内容；管理者在后台查看汇总。
仅使用本机已有 Olivia 账户上传；未配置账户时不上传。`OLIVIA_TELEMETRY_ENABLED=0` 可在进程启动前关闭，或通过受保护的本机配置接口持久关闭。
更换账户会清空待发送记录并轮换会话随机盐，不会把旧账户事件发送到新账户。
关闭立即停止新增记录并清空待发送队列；已经发出的请求不能撤回。
不会扫描并补传更新接入前的聊天历史。现有手动诊断包和 CloudService 登录不受影响。
聊天正文仍由独立的“帮助与改进”机制及其原有设置管理；本次统计不会读取或更改该功能的内容提交设置。

## 记录内容

固定字段：随机事件 ID、设备本地随机盐生成的会话 HMAC、递增序号、时间、阶段、结果、渠道、生成轮次、耗时、固定错误类别、已知模型 ID、客户端版本。
不包含聊天正文、附件、姓名、平台账号、原始会话 ID、异常原文、路径、Key 或 Key 前缀。Key 仅作现有 TLS 账户鉴权，服务端从鉴权结果关联账户。

阶段为启动、聊天渠道连接成功、充值页打开、收到会话条目、生成、校验、媒体、发送和最终回复状态。
后台按账户和会话 HMAC 取最新序号的最终状态，重试不会重复计入逻辑回复数。生成轮次和各阶段失败另列；供应商内部重试不等于客户端生成轮次。
连续聊天输入可能合并，因此收到的会话条目数不等于 QQ 消息条数。主动联系单列。
生成成功不代表校验或发送成功；发送确认不代表用户已读。未确认、处理中、跳过独立展示。
阶段耗时包含实际结束的成功／失败样本；未知耗时保持 null。

## 本机接口

`POST /toy/telemetry/action` 使用现有 Origin、本机地址、确认头和设置会话鉴权。
请求：`{"action":"status"}`、`{"action":"set_enabled","enabled":true}` 或 `{"action":"recharge_page"}`。
关闭使用 `enabled:false`。返回 `{"enabled":false,"last_error":null}`，错误采用既有设置 API 错误码。
充值页请求只是页面访问事件，不能创建订单或声明付款。

## 上报与兼容

`POST /v1/telemetry/events` 请求形状见 `contracts/reply_telemetry.schema.json`。
每 60 秒最多上传 100 个事件；仅完整匹配服务端 accepted ID 列表后删除。
本机队列最多 2000 个事件，7 天过期；状态去重最多 10000 个会话，30 天过期。
队列满时丢弃最旧记录，因此后台始终标注为客户端上报样本，不能宣称全量失败率。
服务端模块在私有 cloud 仓库 `relay/client_telemetry*`，保留 30 天，按账户每天最多接收 20000 个新事件。
服务端未部署、离线、限流或本机统计文件异常不会阻止回信或充值。旧客户端无需提供统计字段。

## 充值口径

账户列表将观察到的使用天数、回信成功、充值页访问与服务端现有订单、余额并列。
有效天数按北京时间收到非主动会话条目的日期去重，启动本身不算有效使用。
“首次成功”只代表上报窗口内首次观察，不能冒充历史首次使用。
充值漏斗以打开充值页的账户为分母，只关联其访问后 24 小时内创建的订单，到账来自该订单的服务端 credited 状态。
窗口截止时仍未付款的订单可能以后付款。无上报不等于停止使用，未充值不能单凭事件推断不满意。

## 微信入口

设置页仅展示 QQ；微信绑定、历史记录和备份协议保留兼容。微信支付充值入口继续使用。

## 验证与上线边界

合成测试覆盖默认启用／关闭、账户切换、隐私字段、重试、未知发送、重复批次、乱序、权限和充值归因。
客户端需发布更新、服务端需单独部署并加入代理路由后，才会收到更新后客户端的真实样本。
