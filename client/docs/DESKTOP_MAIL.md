# 桌面写信与来信提醒

本地客户端恢复原版的 **设置 → 桌面偏好 → 写信**。开启后可从桌面入口进入信箱；客户端运行期间，已送达的未读来信会更新原生红点。

首次升级会通过原生设置接口开启一次写信入口，保存后读回确认；之后关闭开关的选择会保留，重启和再次应用补丁不会强制开启。曲库组件不随这次迁移开启。启动器不再直接改写原生设置文件。

登录后立即查询未读数，此后沿用原版每 60 秒的轮询。打开信箱复用同一个轮询；完全退出客户端后不会继续通知。此功能恢复原生入口和红点，不增加消息正文弹窗或系统通知。

## 信件兼容

未读提醒与信箱使用相同的发布规则：

- 普通回信、主动来信、当前与导入信件均沿用已有状态与阅读标记。
- 草稿、排队、生成失败、静默回复和未到发布时间的信不计入来信。
- 需要等待语音或照片完成才发布的信，在可查看后计入。
- 文字已经可以查看、视频仍在生成或失败的回信，仍可提醒。
- 刷新信箱列表不标记已读；阅读已发布的信后，未读数量更新。

## 安装与回滚边界

原生修复仅适用于受管隔离安装的 `0.0.9.627`，严格核验两个 DLL 的完整哈希，备份完成后再写入。更新前端资源和修改原生显示门禁分别处理，不用旧兼容清单覆盖新版前端。未知 DLL、异常路径或被改动的备份会停止修复。

若需回滚，应完全退出客户端后使用版本回滚和经过哈希核验的原生备份；保留用户信件与设置。不要删除整个 profile，也不要截断原生设置文件。一次性迁移标记保存在客户端已有的 localStorage 中，清空该存储会重新执行首次恢复。

开发验证包括合成信件 HTTP 契约、前端 JavaScript 行为、真实客户端资源隔离副本的语法和补丁幂等，以及 DLL 事务恢复。它们不替代实际桌面显示、窗口位置与点击操作验收。
