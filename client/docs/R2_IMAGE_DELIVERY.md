# 图片按需下载

新安装客户端默认自带 108 个线稿表情包，信件与 QQ/微信都可离线使用；已有客户端应用补丁时保留原生资源中的这套线稿。程序补丁保留图片目录与校验值，不重复携带 PNG、JPEG、GIF、WebP 等图片文件。衣橱包含全部 58 套参考，表情包保留全部 272 个条目；启动和读取目录不下载整批图片。对象存储使用腾讯 COS；本文保留历史文件名以免破坏已有链接。

首次显示衣橱参考或支付二维码时，客户端获取下载票据，从腾讯 COS 下载这一张图片。线稿以外的表情包不再由客户端下载：用户从社区下载页（`/installers/stickers.html`）下载风格包，解压到 `data/sticker-packs`（设置 → 林离怎么回复 → 打开表情包文件夹）；客户端按目录中的文件名、大小与 SHA256 核对后才在 QQ 中提供和发送，未安装的风格不会出现在候选里。图片保存到安装数据目录 `data/image-assets/<类别>/<sha256>/<文件名>`，独立于补丁版本目录。缓存校验通过后直接本地读取，不依赖网络；更新补丁和重新启动保留已下载的图片。图片内容变化时采用新的校验值，下载新版文件。默认线稿直接读取本机客户端资源，聊天发送时可从原生资源提取到同一持久目录。

客户端仅接受目录中的编号与准确的 COS 对象路径，不持有对象存储密钥。下载限制大小并核对 SHA256，使用临时文件和原子替换；过期票据重新获取。失败不落盘为可用图片，也不影响已经完成的文字回信。图片下载本身不走生成或计费链路。关系解锁、QQ 专属表情包范围和每日穿搭选择不变。

部署顺序：先将对应的不可变对象上传并验证到腾讯 COS，配置云端 `OLIVIA_IMAGE_ASSETS_MANIFEST`，接入 GET `/v1/components/images/<类别>/<编号>`（短效签名票据），验证公网票据与文件下载，再允许发布客户端补丁。客户端的 `runtime/image_assets.json` 与服务器使用同一份已验证目录。Nginx 只将准确的图片票据路径转发给现有模型服务，不开放任意对象路径。

衣橱支持云端动态目录：`dynamic-v1` 响应提供逐图校验信息，本机接口保存到 `data/image-assets/wardrobe/catalog/index.json` 后返回本机图片链接。内置清单只用于兼容和初始化；后续云端上新无需重新打客户端补丁。下载时仍逐一校验固定对象地址、大小、类型和SHA256。表情包与UI图沿用其既有清单和安装方式。

此变更的本地回归使用合成下载服务器，不代表新增 COS 对象已上线。必须以真实公网下载验收完成后再发布。
