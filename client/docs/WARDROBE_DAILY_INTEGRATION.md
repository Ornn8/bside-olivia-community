# 每日衣橱

世界页提供独立衣橱入口。用户只能指定风格，不能指定某套衣服或上传生成提示。云端保存偏好，林离在首次需要人物照片时选择当天搭配；同日同一偏好版本复用一套，修改风格立即影响随后接受的新任务。

衣橱提供原版日常和11种服装风格，共58套参考：森女系14套；叛逆学院、工装酷感、领带短裤各1套；暗黑古着4套、法式复古9套、大地色古着3套、日系学院6套、甜美千金6套、复古洋娃娃10套、异域舞台3套。发型保持林离当前长度，服装人台不作为人物身份参考。图片保存在腾讯 COS，首次查看时下载到持久的本地缓存，补丁只包含目录元数据和校验值。

客户端 GET/POST `/toy/world/wardrobe` 代理云端 GET/POST `/v1/wardrobe`。风格写入只允许 `request_id` 和 `style_id`；保存失败保留已确认的偏好。服装领取/购买沿用现有规则，提交 `request_id`、`look_id`、`max_charge_cents`，前三件免费自选，之后每件 ¥5。只有云端确认已拥有的衣服才能进入选装候选；用户指定风格，具体搭配仍由林离选择。客户端仅在成功回执后更新界面。参考图通过本机 `/toy/wardrobe/images/<look_id>` 代理读取，浏览器不持有账号密钥。

衣橱以及图片任务的提交、读取、恢复和取消保留 `X-Olivia-Wardrobe-Protocol: daily-v2`，同时携带 `X-Olivia-Wardrobe-Catalog: dynamic-v1`。云端返回分类、套装、介绍及每张图片的 `image_asset` 校验信息；客户端校验后将图片索引原子写入 `data/image-assets/wardrobe/catalog/index.json`。打开衣橱重新获取目录，首次显示时下载所需图片，已缓存图片可跨重启和补丁离线读取。后续新增分类和服装无需更新客户端或内置图片清单。

首次使用这项能力需要更新客户端一次。保留 v2 可让新客户端读取升级前服务器的服装元数据。新服务器对未声明动态目录的客户端仍投影47套旧目录；新客户端也接受旧目录 `20261004-e94ffc6dd51b` 以及早期6选项目录。固定旧版本仍按其准确编号校验；动态目录限制分类和套装数量，拒绝重复编号、跨风格引用、路径穿越、错误哈希和非指定COS对象地址。服务端价格及领取/购买回执仍是唯一计费依据。

云端返回只读 `media_plan.daily_outfit`，包含日期、时区、偏好版本、风格、套装、目录版本和参考图校验值。旧47套保持原始目录版本和图片哈希，新增11套使用新版本；旧任务按冻结的版本读取原参考图。旧照片请求在持久绑定中保留其声明的目录，不能重选新增款式或覆盖已经确定的新款当日搭配。图片元数据中不支持的新款对旧客户端表示为 `null`，保留字段以免触发“未应用衣橱”的失败。套装信息不能作为用户输入提交。

日期按云端世界时间 Asia/Shanghai 划分。排队跨日、改风格、重新连接和重试都保留原任务冻结的搭配。重复保存同一风格不重选；同日A→B→A产生新的偏好版本。

照片第三视角仅在确认外出时使用朋友帮拍的摄影编排，外出的咖啡店、书店等室内场所也可使用。在家、地点不明或仅准备外出时不启用，不能为摄影效果改变世界地点。

视频后台补送与每日视频换装是独立能力。本次客户端包含原视频订单恢复和后台补送，视频换装仍等待生产渲染接口与真实服装一致性验收，不能以本地合同测试宣称换装上线。
