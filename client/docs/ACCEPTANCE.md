# 林离本地陪伴与 Live 总验收矩阵

状态：门槛定义，未因现有原型文件存在而自动通过（2026-08-12）。
适用环境：Windows、本项目指定目录、RTX 3080 10 GB；实际测试时必须记录驱动、CUDA、Python、组件版本和模型 SHA-256。

B11 的机器可执行 gate ledger、LLM/本地运行时、`legacy_letters` 隔离、生命周期和冻结 reviewer 流程见 [`B11_ACCEPTANCE_STANDARD.md`](B11_ACCEPTANCE_STANDARD.md)。

## 0. 总门槛

只有以下条件同时成立，系统才能标记为 `PASS`：

1. 文本、视觉、听觉、实时、显存、失败降级、安装卸载、数据导入和安全治理的所有适用行均为 `PASS`；任何 `BLOCKED`、`UNVERIFIED`、缺失证据或未解释失败都算总验收失败。
2. 自动化测试命令实际收集到测试项并全绿；每个适用完整测试套件都必须 `collect > 0`，并且实际结果为 `failed=0`、`errors=0`、`skipped=0`。`pytest` 的“无测试收集”、任何 skip、单个接口冒烟、单个模型生成或 README 自述都不能代表全绿。
3. 所有适用正常管线均无阻塞并有真实健康证据：原版 UI/信件、LLM、记忆、ASR、TTS、Live 驱动、原版片段/音乐、安装卸载和降级路径都必须可验证；故障路径可明确返回真实可行动错误，但适用能力的 `UNAVAILABLE` 仍是 `BLOCKED/UNVERIFIED`，不能伪装为 `READY`。
4. 视觉、听觉和文字自动指标及日志都不能单独放行。总控必须实际观看同分辨率同时间点的原版与候选对比、实际听取关键音频并实际阅读关键文本；唯一独立 `gpt-5.6-luna/xhigh` reviewer 必须先审查测试与 diff 并明确 `PASS`。
5. 所有真实密钥、令牌、玩家资料、原版程序/解包资产、模型权重和生成媒体只在本机测试，不能出现在 Git、日志、截图、报告或分发包。

## 1. 证据包格式

每次验收建立一个本机、不进 Git 的证据目录，至少包含：

- `environment.json`：操作系统、GPU、驱动、CUDA、Python、组件版本、权重哈希和磁盘/显存容量。
- `test-results.xml` 或等价完整测试日志：测试收集数量、通过/失败/跳过、命令和退出码；不能只保存最后一行。
- `trace.jsonl`：请求/会话 ID、阶段时间戳、降级原因、错误码；内容必须脱敏。
- `visual/`：原版基准截图/片段、候选截图/片段、同分辨率同时间点对照、遮罩说明、指标报告；媒体只放本机证据目录。
- `audio/`：原版参考、ASR 转写、TTS 输出、采样率/时长/峰值/同步报告和人工听审记录；不把音频复制进仓库。
- `install/`：干净环境安装、停用、卸载、回滚和重新安装的命令/日志。
- `review.md`：冻结最终 diff 后创建的唯一独立 `gpt-5.6-luna/xhigh` reviewer 的测试、diff、版权/隐私边界和明确 `PASS`/`FAIL` 结论；总控的多模态观看、听审和阅读结论单独签名。

测试数据与校准/模型选择数据必须分离；保留集只用于最终评估，不能为了过门槛反复调参。所有证据都要标注“实测”“自动指标”“人工观看/听审”或“未验证”。

## 3. 视觉基线与阈值批准流程

视觉阈值不得由执行者为了过关随意放宽。流程固定为：

1. 执行者从原版本机资产中登记基准截图/参考片段，记录原始分辨率、帧率、状态、时间点、动态口部 mask 和静态区域 mask；原始媒体不进 Git。
2. 在完全相同的分辨率、裁剪、时间点、色彩空间和输出编码下测量：静态区域 `mean_abs_RGB`/`P95_abs_RGB`、SSIM、LPIPS、面部身份相似度、边缘闪烁、背景光流/漂移、色差（Delta E）、帧率和音画同步偏差。
3. 把每个指标的数值阈值、统计口径、排除区域和允许误差写入本机 baseline manifest；首次测量前阈值为空，任何空阈值只能是 `UNVERIFIED`，不能是 `PASS`。
4. 实施任务冻结最终 diff 后，恰好创建一名独立 `gpt-5.6-luna/xhigh` reviewer 审查原版基线、测量方法、阈值和最终 diff，确认阈值没有因候选输出变差而被事后放宽；明确 `PASS` 后才可交总控。
5. 候选输出必须同时通过自动指标和总控多模态观看。面部身份、背景、构图或清晰度出现主观明显退化，即使自动指标通过也失败。

## 4. 建议的测试命令与解释

命令必须在证据包中记录实际退出码、收集数量以及通过/失败/错误/跳过数量；每个适用完整测试套件都必须实际收集且 `failed=0`、`errors=0`、`skipped=0`。以下只是最低入口，不是替代完整测试套件：

```powershell
rtk pytest -q
rtk python -m compileall -q <source-roots>
rtk python <component-healthcheck.py> --profile core
rtk python <e2e-harness.py> --case-set holdout --evidence-dir <local-evidence>
```

如果没有测试文件、pytest 收集为 0、任何测试被跳过、组件因缺权重而不可用，或适用管线真实 `UNAVAILABLE`，结论必须是 `UNVERIFIED/BLOCKED`，不能写成“测试通过”或 `READY`。
