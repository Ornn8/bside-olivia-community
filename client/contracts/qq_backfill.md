# QQ 补拉接入前检查

当前 `qq.backfill_enabled` 默认 `false`。设为 `true` 仍返回
`QQ_BACKFILL_UNAVAILABLE`，实时收发继续；当前构建不会发出补拉 action。

仓库的 `napcat_installer.py` 固定 v4.18.28，`napcat_bundle.py` 提供打包下载、
大小和摘要校验；仓库内没有该分发包的 action 实现或对应接口契约。
不能据 `get_friend_msg_history` 这个名称推断参数、分页方向或消息标识语义。

接入前需从实际打包构建确认：action 名称；请求字段类型及合法范围；响应
成功/错误格式；消息 ID 是否稳定、是否与事件推送一致；分页锚点是否包含
自身、结束条件、排序与并发新消息行为；消息时间的单位和时区；仅限好友还是
也支持临时会话；图片/文件引用生命周期与撤回表现；可检索时间范围和限流。

确认接口后按以下持久化协议实现，不另建消息去重机制：

1. 绑定成功时写入 binding_id、绑定代次、绑定起始时间和平台支持的起始锚点。
   首次启用已有绑定也从启用边界建立锚点，不导入以前未答的消息；没有可信
   锚点或时间时禁用补拉，不猜测先后。更换账户、联系人或重新绑定清空游标。
2. 游标保存于绑定自己的状态记录，至少包括 schema、绑定代次、平台锚点、
   最后已持久化事件 ID、时间边界；不放入遥测。
3. 登录身份验证通过后才启动补拉。每次最多 3 页、100 条、5 秒，任一预算
   耗尽停止并持久化进度；这些是拟定客户端限制，不能代替平台接口参数确认。
4. 接收实时事件与补拉都调用现有 ingest，使用相同 message_id/source_messages。
   允许边界重叠，先持久化该页全部合格消息，成功后才推进游标；落盘失败
   不推进。排除本人发出的消息、其他联系人及绑定边界之前的消息。
5. 回复队列仍由 RECEIVED/安全 GENERATED 驱动；SENDING/UNKNOWN 不因补拉重发。
   主媒体使用独立 outbox。重复页、重启和分页期间的新输入必须幂等。

## 真实测试账号验收清单

- 记录实际 NapCat 构建及包摘要，确认 action 的实现文件与字段契约。
- 连续发送文字、图片、文件、语音；对比实时推送与补拉 ID/时间/附件引用。
- 断开 Olivia WS 后发送多条，重连后每条仅入库一次且顺序正确。
- 分页期间继续发送；覆盖边界重复项、乱序返回、相同时间戳、空页和限流。
- 页内落盘失败及写入后推进游标前强制退出；恢复后不漏收、不重复回复。
- 设置开关前、绑定前的旧消息不进入回复队列；更换联系人或机器人不跨绑定。
- 发送成功但 ACK 丢失的消息不因补拉再发；已完成主图片不再生成或发送。
- 超预算停止，不妨碍实时收件、连接测试和关闭应用；默认关闭时零补拉请求。
- 登录失效、等待扫码、没有权限、接口不存在均显示有限错误，禁止无界重试。

完成上述验证、补齐合成协议测试后，才能将开关从“不可用”接到实际适配器。
